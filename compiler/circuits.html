CCDL, PCBA and CAS-Ohm

Use CAS to describe a state. Use CCDL to describe how named states and components connect. Use CAS-Ohm when you want exact arithmetic on explicitly declared quantities and units.

CCDL: a circuit written as text

CCDL means Cognitive Circuit Description Language. It declares named states, parts, connections and observation points. A circuit describes what connects. A board can also arrange states on P, C, E and O domain layers, with via connections between them.

Think of a team’s decision process. A question enters, a standing belief or policy influences how it is handled, and an answer follows. A circuit model makes those roles explicit. You decide what the nodes mean and which connections to declare; the compiler checks the supported structure and produces its graph.

CauseWhat enters
+
BiasWhat controls the response
→
EffectWhat comes out

Conceptual role diagram for a CJT. The plus above means two input roles, not a CAS addition expression.

CJT<cause | bias => effect> writes those three terminal roles. The angle brackets contain them, the pipe separates cause and bias, and => introduces the effect terminal.

PCBA: the cognitive circuit model

CAS PCBA Engineer develops cognitive circuits using component concepts. In this Site, select CCDL / PCBA to author their declarations. The table separates each conceptual role from the current software behavior.

PartCognitive modelCurrent implementation
CJT — Cognitive Junction TransistorA cause input, bias/control input and effect output. The response depends on the bias and declared parameters.Checks terminals and parameters. A selected fixed-bias simulation applies gain, cutoff and saturation.
Resistor / RA declared constraint on flow.Checks its declaration. The selected CAS-Ohm resistor profile calculates flow from drive and constraint.
Capacitor / C / leakageStored accumulated experience, with capacity and decay concepts.Checks declarations and parameters. Storage and forgetting dynamics are not simulated.
Inductor / LPersistence in a pattern: resistance to changing its flow.Checks the declaration. Habit dynamics are not simulated.
Layer / viaGroup states by domain and declare a connection between layers.Checks layer/domain consistency and supported downward connections.
ProbeName an observation point.Records the target. Supported simulations also report its calculated value.

A component’s cognitive meaning is a modeling choice documented in the book. A structural result tells you what was declared and checked. For numerical traces, choose an implemented simulation profile and supply its inputs.

Read the supplied “Pcba Schematic”

// Authored structural example; execution and measured cognition are unavailable.
// I/O terminals are declared but untyped and deliberately unconnected.
// The checker must warn about them; it must not invent prompt-to-response wiring.
circuit guarded_chain {
    input: prompt;
    output: response;
    node question: ^8^C_{F2}|A;
    node charter: ^5^P_{F7}|T;
    node answer: ^9^C_{F6}|A;
    cjt decision: CJT< question | charter => answer > [beta=0.5, gm=0.1, sat=0.95, cutoff=0.1];
    resistor restraint: Resistor< question, R=30 >;
    capacitor memory: Capacitor< charter, C=10, leakage=0.01 >;
    inductor habit: Inductor< answer, L=1 >;
    probe tp_answer: answer;
}
Read it one declaration at a time
CodeExplanation
circuit guarded_chain { … }Names the design and encloses its declarations. Each semicolon ends a declaration. Lines starting // are comments.
input: prompt; output: response;Declares I/O terminal names. In this particular example they remain unconnected; the checker warns about that.
node question: ^8^C_{F2}|ANames a Cognitive state with Above/Cause, Wisdom and Analytical register. This node is the cause terminal.
node charter: ^5^P_{F7}|TNames a Principled state with Female, Purpose and Transcendent register. It supplies the bias role.
node answer: ^9^C_{F6}|ANames a Cognitive state with Below/Effect, Structure and Analytical register. It supplies the effect role.
cjt decision: CJT< question | charter => answer >Names the component and connects its cause, bias and effect terminals.
[beta=0.5, gm=0.1, sat=0.95, cutoff=0.1]Square brackets hold named parameters. beta is gain; gm is a declared transconductance parameter; sat is the cap and cutoff the bias threshold. This structural example includes parameters outside the fixed-bias numerical profile.
Resistor< question, R=30 >Declares constraint at question. The comma separates the terminal from its parameter.
Capacitor< charter, C=10, leakage=0.01 >Declares capacity and leakage at charter.
Inductor< answer, L=1 >Declares an inductor at answer.
probe tp_answer: answerNames an observation point on answer.

What its graph and result mean

The graph records named items and checked terminal relationships. In this supplied schematic the CJT contributes two directed relationships: cause to effect and bias to effect. Follow the labels to tell them apart. Other components keep declaration records; a visible component record alone does not indicate numerical execution.

Read the structural status, diagnostics and declaration/netlist data. The unconnected I/O warnings are useful: they tell you exactly which connections the source has yet to declare.

Editable variation: change the declared gain

Change beta=0.5 to beta=0.8 and compile again. Compare the stored CJT parameter and structural diagnostics. That changes the declared design. To calculate a scalar response, load the separate Fixed Bias example with its supplied simulation inputs.

Run the supported fixed-bias model
output = 0                        when bias < cutoff
output = min(sat, beta * cause)    otherwise

The profile cas.pcba.scalar-fixed-bias/0.1 makes this equation explicit. A fixed bias controls whether the component conducts; beta scales the cause; sat caps the result. It uses declared scalar activations and exact fractions. The supplied Fixed Bias example produces 2/5, 17/20, 17/20, 0 over its four steps.

CAS-Ohm: explain the numbers before calculating

CAS-Ohm relates three quantities on a scale you declare. Drive is the driving potential, attention is the flow, and constraint relates the two. The scale identifies compatible units; provenance records where the values came from.

12declared-drive units
÷
4declared-drive per declared-attention
=
3declared-attention units

The actual “Ohm Flow” example

let scale: ohm_scale = ohm_scale("example-v1", "declared-drive", "declared-attention")
let potential: ohm_drive = ohm_drive("12", scale, "design", "example:potential")
let resistance: ohm_constraint = ohm_constraint("4", scale, "design", "example:constraint")
ohm_flow(potential, resistance)
PartMeaning
let scale: ohm_scale = ohm_scale(…)Names a scale. The first string is its ID; the next strings name drive and attention units.
ohm_drive("12", scale, "design", "example:potential")Constructs a drive quantity. "12" preserves the numeric input exactly; scale identifies the units; "design" marks a chosen design input; the final string is its source reference.
ohm_constraint("4", scale, "design", "example:constraint")Constructs a compatible constraint quantity, with units drive/attention and its own source reference.
ohm_flow(potential, resistance)Divides drive by constraint and returns attention flow. Parentheses hold the arguments; the comma separates them.

Read the output

The exact value is 3/1, or 3 declared-attention units. Inspect the scale, quantity kind, input origins and source references alongside the number. The source labels are authored metadata; the arithmetic checks scale compatibility and rejects zero denominators. Its calibration status remains NOT_VERIFIED until separate calibration evidence exists.

Load Ohm Flow

Editable variation: change the drive, keep the constraint

Change ohm_drive("12" to ohm_drive("16". Keep constraint 4 and the same scale. Run again: flow is exactly 4/1. You have explored the arithmetic consequence of a declared change; any interpretation of a real person needs its own observations and measurement definitions.

The other two calculations

ohm_required_drive(attention, constraint) multiplies attention by constraint. ohm_effective_constraint(drive, attention) divides drive by attention. Their supplied examples retain units and provenance. The Ohm Exact Fraction example returns 1/3 exactly.
